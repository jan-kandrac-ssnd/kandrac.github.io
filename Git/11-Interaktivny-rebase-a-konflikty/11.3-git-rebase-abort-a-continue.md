# 11.3 `git rebase --abort` a `--continue`

Pri riešení konfliktov (ale aj kedykoľvek inokedy počas interaktívneho rebase) máš k dispozícii dva dôležité
príkazy, ktoré ti pomôžu sa v celom procese zorientovať.

## `git rebase --continue`

Tento príkaz sme si už ukázali v predchádzajúcej lekcii - povie Gitu "vyriešil som konflikt (alebo dokončil úpravy
pri `edit`), pokračuj ďalším commitom v zozname".

```bash
git rebase --continue
```

Ak zabudneš vyriešiť konflikt (alebo pridať súbor pomocou `git add`) a napriek tomu zavoláš `--continue`, Git ťa
na to upozorní a rebase nedokončí.

## `git rebase --abort`

Niekedy zistíš, že rebase spravil viac problémov ako úžitku - konfliktov je priveľa, alebo si si to jednoducho
rozmyslel. V takom prípade máš možnosť **celý rebase zrušiť** a vrátiť sa presne do stavu pred jeho spustením.

```bash
git rebase --abort
```

> **Dôležité:** `git rebase --abort` je bezpečná "záchranná brzda" - história repozitára sa vráti presne do
> stavu, v akom bola pred zavolaním `git rebase -i`, akoby si rebase nikdy nespustil.

## `git rebase --skip`

Bonusový, menej používaný príkaz - ak sa počas konfliktu rozhodneš, že konkrétny commit **vôbec nepotrebuješ**
aplikovať (podobne ako `drop`), vieš ho jednoducho preskočiť:

```bash
git rebase --skip
```

## Zhrnutie príkazov

| Príkaz                  | Význam                                           |
|-------------------------|--------------------------------------------------|
| `git rebase --continue` | Pokračuj po vyriešení konfliktu / úprave commitu |
| `git rebase --abort`    | Zruš celý rebase, vráť sa do pôvodného stavu     |
| `git rebase --skip`     | Preskoč aktuálny commit a pokračuj ďalej         |

> **Tip:** Ak si nie si istý, v akom stave sa rebase práve nachádza, `git status` ti vždy napovie, či prebieha
> rebase, ktoré súbory sú konfliktné a aké príkazy môžeš použiť.
